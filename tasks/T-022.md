## Goal

Introduce the `provider:` config key and a dynamic loader that picks the right `TaskProvider` at runtime. Built-in providers (`file`) load directly; external providers (`jira`, `linear`, `<custom>`) are dynamically imported from `@frehilm/ordna-<name>`. After this PR, swapping backends is a one-line change in `.ordna/config.yaml`.

## Acceptance Criteria

- [x] `OrdnaConfig` (Zod schema in `packages/core/src/config.ts`) gains `provider: z.string().default("file")`
- [x] Optional plugin-specific config blocks accepted (`.passthrough()` on the schema; validation deferred to the plugin)
- [x] New file `packages/core/src/providers/load.ts` exports `loadProvider(config, cwd): Promise<TaskProvider>`
- [x] `loadProvider("file", ...)` returns a `FileTaskProvider` instance (T-021)
- [x] `loadProvider("<other>", ...)` does `await import("@frehilm/ordna-<other>")` and calls its `createProvider(config, cwd)` factory
- [x] If the external package isn't installed, throw a clear error with the install command:
  > Provider "jira" not installed. Run: `pnpm add @frehilm/ordna-jira`
- [x] If the external package doesn't export `createProvider`, throw a clear error explaining the contract
- [x] Zero-config behavior unchanged — no `.ordna/config.yaml` still resolves to `FileTaskProvider`
- [x] New unit tests cover: file resolves correctly; missing plugin produces the install-command error; malformed plugin produces the contract error

## Notes

Each plugin package is expected to export a single factory:

```ts
// @frehilm/ordna-jira/src/index.ts
export function createProvider(config: OrdnaConfig, cwd: string): TaskProvider {
  return new JiraTaskProvider(config, cwd);
}
```

This is the entire plugin contract — opinionated and tiny. Plugins can use any internal organization they want as long as `createProvider` is exported.

Recommended decision (from T-018 §"Open questions"): **explicit install** of external providers, not auto-install. Users see an actionable error rather than magic side effects.
