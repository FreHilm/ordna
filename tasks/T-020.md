## Goal

Introduce a `TaskProvider` interface in `@frehilm/ordna-core` that abstracts the storage layer. This is the smallest landable change in Phase 1 of T-018 — it adds the type definitions without changing any runtime behavior. Once this lands, the rest of the refactor and the actual plugin implementations have a clear contract to target.

## Acceptance Criteria

- [x] New file `packages/core/src/provider.ts` exports `TaskProvider` interface
- [x] Interface methods cover the existing core API: `list`, `get`, `create`, `update`, `move`, `delete`, `watch`
- [x] Optional methods on the interface for backend-specific lifecycle: `commit?` (file-only), `init?`, `dispose?`
- [x] Interface declares a `kind: string` field for diagnostics ("file" / "jira" / "linear")
- [x] `TaskEvent` and `ListOptions` types are co-located in `provider.ts` and exported from core's index
- [x] `Task` type's `filePath` and `rawContent` fields become optional (file-only)
- [x] `Task` gains optional `remote?: { provider: string; externalId: string; extras?: Record<string, unknown>; url?: string }` for surfacing remote-only metadata in the UI
- [x] No runtime code uses the interface yet — this PR is types-only
- [x] Existing tests pass without modification

## Notes

Proposed interface shape (final wording can change during implementation):

```ts
export interface TaskProvider {
  list(opts?: ListOptions): Promise<Task[]>;
  get(id: string): Promise<Task | null>;
  create(input: TaskCreateInput): Promise<Task>;
  update(id: string, patch: TaskUpdateInput): Promise<Task>;
  move(id: string, status: string): Promise<Task>;
  delete(id: string): Promise<void>;
  watch(cb: (event: TaskEvent) => void): () => Promise<void>;
  commit?(message?: string): Promise<void>;
  init?(): Promise<void>;
  dispose?(): Promise<void>;
  readonly kind: string;
}
```

The `Task.remote` field is what lets UIs render an "Open in Jira" link or a sprint chip without `Task` itself having to model every concept Jira / Linear support.
