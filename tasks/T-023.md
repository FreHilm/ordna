## Goal

Complete the implementation of the `TaskProvider` lifecycle: `init` runs once when the context is created, `dispose` runs at every clean shutdown path. This closes out the remaining technical work for Phase 1 of the plugin architecture. **No release in scope** — version bump, changeset, tag, and publish all live in T-030.

The async `createContext` migration and CLI/Web callsite updates were absorbed into T-022 to avoid a two-API limbo, so this task focuses purely on lifecycle wiring.

## Acceptance Criteria

- [x] `createContext` calls `await provider.init?.()` once, after instantiation and before returning the context
- [x] `runWeb`'s `close()` calls `await ctx.provider.dispose?.()` after the watcher unsubscribe
- [x] CLI commands that hold a long-lived context (`web`, `board`) call `await ctx.provider.dispose?.()` on shutdown / signal handlers
- [x] One-shot CLI commands (`create`, `list`, `show`, `move`, `assign`, `commit`) do not need to call `dispose` — they exit naturally and the provider is GC'd; document this in a comment
- [x] TUI unmount path (`runBoard`'s `waitUntilExit` finally) calls `await ctx.provider.dispose?.()`
- [x] `FileTaskProvider.init` already exists (lazy mkdir of `tasksDir`); leave it untouched
- [x] `FileTaskProvider.dispose` already closes tracked chokidar watchers; verify it's idempotent (safe to call twice)
- [x] New core unit test: provider with stubbed `init` / `dispose` is invoked exactly once each across the createContext → use → shutdown lifecycle
- [x] `pnpm -r typecheck`, `pnpm -r build`, `pnpm -r test` all green
- [x] No version bump. No changeset. No CHANGELOG entry. No publish. (Those live in T-030.)

## Notes

`init` is the place for remote providers (Jira / Linear) to validate auth or fetch a status mapping at startup. The file provider's `init` is a cheap mkdir we already had — keep it. Without this lifecycle hook wired, future remote providers couldn't surface "your auth token has expired" until the first network call deep inside `list()`, which is a worse UX.

`dispose` is the symmetric cleanup: chokidar watchers, HTTP keep-alive sockets, GraphQL subscriptions, anything a remote provider opens. The file provider already tracks watchers in `Set<FSWatcher>` for this exact purpose — make sure calling `dispose` twice doesn't throw.

When this task lands, Phase 1 is technically complete. T-024 (docs + verification) and T-030 (release) follow.
