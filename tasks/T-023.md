## Goal

Make `createContext` async (it now needs to `await loadProvider(...)`) and update every callsite in `@frehilm/ordna-cli` and `@frehilm/ordna-web` to `await` it. This is the breaking change in the Phase 1 chain — bumps all packages to `0.2.0`.

## Acceptance Criteria

- [ ] `createContext(cwd?: string): Promise<StoreContext>` is async
- [ ] `StoreContext` gains `provider: TaskProvider` field
- [ ] `createContext` calls `provider.init?.()` once at startup
- [ ] CLI commands (`init`, `list`, `show`, `create`, `move`, `assign`, `commit`, `web`, `skill`, board) all `await createContext(...)`
- [ ] Web server's `runWeb()` and any in-process callers `await createContext(...)`
- [ ] TUI's `App.tsx` `useState(() => createContext())` lazy initializer is replaced with an effect that resolves the promise and stores the context (loading state until resolved)
- [ ] Watcher cleanup calls `provider.dispose?.()` on unmount / shutdown
- [ ] All 37 existing tests still pass (modulo the `await` syntax updates in test setups)
- [ ] Version bumps: all three workspace packages from `0.1.x` to `0.2.0`
- [ ] CHANGELOG entry (or changeset markdown) covers the breaking signature change

## Notes

This is the public API break that motivates a minor bump (we're pre-1.0, so minor is the breaking-change channel). External library consumers (the IDE) need to update their own `await` usage, but the import surface and behavior are otherwise unchanged.

For the TUI, the cleanest pattern is:

```tsx
const [ctx, setCtx] = useState<StoreContext | null>(null);
useEffect(() => {
  createContext().then(setCtx);
}, []);
if (!ctx) return <Text>Loading…</Text>;
// rest of App
```

— shows a loading flash for a few ms while the file provider's `init()` runs (mostly negligible for `FileTaskProvider`, more visible later when Jira/Linear hit network).

Don't ship Phase 2 (Jira) before this lands — Jira plugin requires the async loader to even be importable.
