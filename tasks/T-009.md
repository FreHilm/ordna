## Notes

### Field mapping

Linear's model is closer to Ordna's than Jira's, so the table is shorter:

| Ordna `Task` field         | Linear field                  | Direction |
|----------------------------|-------------------------------|-----------|
| `id`                       | Linear identifier (`ENG-42`)  | r/w |
| `title`                    | `title`                       | r/w |
| `status`                   | `state.name`                  | r/w |
| `assignee`                 | `assignee.displayName`        | r/w |
| `priority`                 | `priority` (1-4) → `high`/`medium`/`low`/null | r/w |
| `tags`                     | `labels.nodes[].name`         | r/w |
| `depends_on`               | `relations` where `type == "blocks"` (inverse) | r/w |
| `sections`                 | `description` (markdown native — no translation) | r/w |
| `remote.extras.cycle`      | `cycle.name`                  | r |
| `remote.extras.project`    | `project.name`                | r |
| `remote.extras.parentIssue`| `parent.identifier`           | r |

### Why depends on T-008

T-008 lands the field-mapping conventions, the `Task.remote.extras` blob shape, the polling-watcher pattern, and the rate-limit handling. T-009 is largely a different transport over those same primitives. Building T-009 second avoids repeating those decisions and lets us move shared helpers into core (or a common subpackage) if patterns emerge.

### Real-time

Linear has GraphQL subscriptions over WebSocket — first-class real-time updates without polling. v1 should use subscriptions when available, polling as fallback (e.g. behind a corporate firewall that blocks WS).

## Progress

- 2026-05-14: Started. Decisions confirmed with user: (1) Hybrid watch — try GraphQL subscription over WebSocket first, fall back to polling on connect failure or downgrade. Adds `graphql-ws` as a dep. (2) Duplicate the `linearKeyToOrdnaId` / `ordnaIdToLinearKey` helpers in this package — no shared utility extraction. Same `~10 LOC` shape as Jira but kept here to avoid cross-plugin coupling.
- 2026-05-14: Implemented. New package `packages/linear/` (~700 LOC source + ~390 LOC tests + README):
  - `src/schema.ts` — narrow TS types for the Linear GraphQL slice we consume (issue, workflow state, viewer, paginated response envelope, error shape).
  - `src/client.ts` — GraphQL POST client. Single `query<T>` helper handles auth (`Authorization: <key>`), 429 with `Retry-After` honour, exponential backoff with jitter for transient 5xx, and translation of GraphQL-200-with-errors payloads into thrown `Error`s carrying every `errors[].message`. Pagination uses `pageInfo.endCursor` for cursor-based traversal.
  - `src/map.ts` — pure issue → Task mapping. Same shape as Jira's: identifier rewriting both ways, priority collapse (Linear's 0–4 scale into Ordna's high/medium/low/null), `depends_on` filter on `blocks` relations, description wrapped as a single `## Description` section (no ADF — Linear stores markdown natively), extras populated for cycle / project / parent issue when present.
  - `src/subscription.ts` — `graphql-ws` wrapper. Tries to open a subscription on `wss://api.linear.app/graphql`, resolves the outer promise once an event arrives (or after a 1s connect-quiet window). On error before establishment, rejects so the provider falls back to polling. Documented as speculative — Linear's public docs don't currently advertise WS subscriptions.
  - `src/provider.ts` — `LinearTaskProvider` class. `init()` discovers the team's workflow states via `team(id) { states { nodes } }`, sorts by `position`, overwrites `config.statuses` so the board shows native column names. Hybrid `watch()`: tries the subscription via `subscribeToIssues`; on any failure (`subscription unavailable (…)`), drops to polling at `pollIntervalMs`. Diff-and-emit shape matches Jira's. `dispose()` closes the subscription if open and clears the polling timer; idempotent. Write methods stubbed with clear "not implemented in 0.1.x" errors. Team-prefix is cached lazily on first `list()` so `get()` can resolve Ordna IDs back to Linear identifiers without a separate round-trip.
  - `src/index.ts` — `createProvider(config, cwd)` factory + selected re-exports.
- 2026-05-14: Tests. 19 tests across 2 files:
  - `map.test.ts` (12) — identifier rewriting both ways, Linear's full priority scale (urgent/high/medium/low/none), `blocks`-relation filtering, description→sections wrap, missing-description path, extras population for cycle/project/parent.
  - `provider.test.ts` (7) — integration with a stubbed `node:http` GraphQL endpoint. Covers init-time status discovery + `config.statuses` override, list mapping + sort, get-by-Ordna-id roundtrip (uses cached team prefix), null on missing issue, 429 retry-and-succeed, dispose idempotency, write-method "not implemented" assertions.
