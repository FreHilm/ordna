## Goal

Document the plugin architecture for both end-users and plugin authors, then ship the version bump that includes T-020 → T-023. This task closes Phase 1 of T-018; Phase 2 (Jira plugin via T-008) and Phase 3 (Linear plugin via T-009) can ship independently after this.

## Acceptance Criteria

- [ ] Root `README.md` gains a "Backends" section under "Packages" explaining `provider:` config, with a small table linking to plugin packages once they exist
- [ ] `packages/core/README.md` documents the `TaskProvider` interface and the `createProvider` factory contract
- [ ] `packages/core/README.md` adds a "Writing a provider" guide: minimum example, lifecycle (`init`/`dispose`), `commit` semantics, error conventions
- [ ] `packages/cli/templates/AGENTS.md` (the AI skill) mentions the existence of plugins and the `provider:` config key — agents need to know about the swappable backend

- [ ] Manual smoke test against the existing `tasks/` directory in this repo confirms no regression in `FileTaskProvider` mode
- [ ] `pnpm -r build` and `pnpm -r test` green
- [ ] Tag and publish via the existing release pipeline (T-019 / changesets workflow once that lands)

## Notes

Recommended changeset wording (drop in `.changeset/plugin-architecture.md`):

```markdown
---
"@frehilm/ordna-core": minor
"@frehilm/ordna-web": minor
"@frehilm/ordna-cli": minor
---

Introduce pluggable storage backends via the new `TaskProvider` interface.
The built-in `FileTaskProvider` is the default; external providers can be
configured via `provider:` in `.ordna/config.yaml` and will be loaded from
`@frehilm/ordna-<name>` if installed.

BREAKING: `createContext` is now async. All consumers must `await` it.
```

When `@frehilm/ordna-jira` (T-008) and `@frehilm/ordna-linear` (T-009) ship later, this task's docs should be revisited to add their READMEs into the "Backends" table — but that work is owned by the respective plugin tasks.
