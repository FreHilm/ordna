## Goal

Add an opt-in `TaskProvider` that stores tasks as git blobs under `refs/ordna/tasks/<id>` instead of as `.md` files in the working tree. For users who want git-native, decentralized task management but don't want `tasks/` polluting their repo. Inspired by [git-bug](https://github.com/git-bug/git-bug)'s ref-namespace approach, but deliberately simpler — no CRDT op-log, just one blob per task at one ref per task.

Activated by a single config line:

```yaml
# .ordna/config.yaml
provider: ref
```

Tasks become invisible to the working tree, ride alongside the repo via `git push origin 'refs/ordna/tasks/*:refs/ordna/tasks/*'`, and survive branch switches without touching `git checkout` semantics.

## Acceptance Criteria

- [x] New package `@frehilm/ordna-ref` exporting `createProvider(config, cwd): TaskProvider`
- [x] Implements all required `TaskProvider` methods: `list`, `get`, `create`, `update`, `move`, `delete`, `watch`
- [x] `kind === "ref"`
- [x] All persistence goes through `git` plumbing: `git hash-object -w` to write, `git cat-file blob <oid>` to read, `git update-ref refs/ordna/tasks/<id> <oid>` to commit, `git for-each-ref refs/ordna/tasks/` to list
- [x] `commit()` is a no-op (tasks live outside the working tree, no `git commit` step needed) — or aliased to push
- [x] `watch()` polls `git for-each-ref` on a configurable interval (default 1s) and emits `TaskEvent`s in the same shape as `FileTaskProvider`
- [x] Concurrency: refuses non-fast-forward `update-ref` (using `git update-ref --create-reflog <ref> <new> <expected-old>`), surfaces a clear "ref moved underneath you, refresh and retry" error
- [x] Conflict policy documented in the package README — what happens when two machines edit the same task and both push
- [ ] New optional CLI command `ordna sync` (or just clear docs for the user-managed refspec) that runs `git push origin 'refs/ordna/tasks/*:refs/ordna/tasks/*'` and the equivalent fetch — *docs in README; the `ordna sync` CLI command is a follow-up that touches `@frehilm/ordna-cli` rather than this package*
- [x] Unit tests for the provider: round-trip a task; verify `tasks/` directory is never created/touched; verify two concurrent writers cause the second one to fail with the documented error
- [x] Integration test: spin up a tmp git repo, install the provider, run through the standard CLI flow (create / list / move / delete) and assert the working tree is clean throughout

## Notes

**Why ship this after T-008 (Jira) and T-009 (Linear), not before:**
Jira and Linear cover the larger user demand for "I don't want task files in my repo." Most users asking that question want a real tracker. The ref provider is for the narrower audience that wants git-native + decentralized + no working-tree clutter. It's also the smallest of the three providers (~200–300 LOC for v1) and adding it later costs nothing because the loader (T-022) already supports any `@frehilm/ordna-<name>` package.

**Trade-offs to call out in the README:**

1. *Watch is polling, not push.* Refs don't have a kernel-level change notification path the way the filesystem does, and watching `.git/refs/ordna/` directly breaks the moment git packs refs. Polling at 1s is simple and reliable; users on huge repos can configure a higher interval.

2. *`git push` no longer auto-syncs your tasks.* Refs outside `refs/heads/*` don't ride along by default. We either ship `ordna sync`, or document the one-time `git config --add remote.origin.push '+refs/ordna/tasks/*:refs/ordna/tasks/*'` setup. The latter is more honest about what's happening; recommend documenting both.

3. *Conflict resolution is harder than with files.* Plain `tasks/*.md` get `git merge` for free. Refs don't get a merge driver, and a `git push --force` from one machine silently overwrites the other's edits. The provider should refuse non-fast-forward `update-ref` and require the user to refresh + retry. We deliberately do *not* implement a CRDT op-log here — that's git-bug's domain and a 10× scope explosion.

4. *`cat tasks/T-001.md` no longer works.* Tasks are git blobs, not files. Reading requires `ordna show T-001`. This is the price of the working-tree-clean property and should be stated up front; users who care about file-level editability shouldn't pick this provider.

5. *Agent integration weakens.* Claude / Cursor / similar tools edit `tasks/T-005.md` directly today. With the ref provider they'd need to shell out to `ordna` for every mutation. The AI skill (`AGENTS.md`) should grow a "if `provider: ref`, use these commands instead" note as part of this task.

6. *Backlog.md compatibility doesn't apply* — Backlog expects files. Document that `schema: backlog` + `provider: ref` is unsupported and the loader should error early on that combination.

**Sketch of the core API surface** (final shape can change during implementation):

```ts
// @frehilm/ordna-ref/src/index.ts
import { execFileSync } from "node:child_process";
import type { TaskProvider, OrdnaConfig } from "@frehilm/ordna-core";

const REF_PREFIX = "refs/ordna/tasks/";

export function createProvider(config: OrdnaConfig, cwd: string): TaskProvider {
  return new RefTaskProvider(cwd, config);
}

class RefTaskProvider implements TaskProvider {
  readonly kind = "ref";
  // list/get/create/update/move/delete: shell out to git plumbing
  // watch: setInterval(() => diff(currentRefs, lastRefs), pollMs)
}
```

**Push/pull UX recommendation:**
Don't make users edit their `.git/config` manually. Ship `ordna sync` as a tiny wrapper that does the push and fetch with the right refspec. It's the only piece of the existing CLI that needs to know about the ref backend explicitly — every other command goes through `TaskProvider` and is provider-agnostic.

- 2026-05-14: Started. Reasonable-call decisions: (1) Reuse `serializeTask` / `parseTask` from `@frehilm/ordna-core` so the blob format is byte-identical to file-mode markdown — tasks can be exported back to files later. (2) `commit()` is a no-op; the AC's "or aliased to push" alternative would push every mutation which is too eager. Document the manual refspec / `git push refs/ordna/tasks/*` in the README instead of shipping `ordna sync` (that CLI piece is a separate cross-package follow-up). (3) Shell out via `node:child_process.execFile` (async, no shell parsing) — zero deps, fits the plugin ethos.
- 2026-05-14: Implemented. New package `packages/ref-provider/` (~430 LOC source + ~260 LOC tests + README):
  - `src/git.ts` — thin async `GitRunner` wrapper around the `git` binary. Initially used `execFile`'s promisified form but discovered the hard way that `execFile`'s `input` option is silently ignored (only `execFileSync` / `spawnSync` honour it) — `git hash-object --stdin` hung waiting for input. Switched to `spawn` with explicit `proc.stdin.write(...)` to pipe input deterministically. Surfaces `git`'s stderr verbatim on failure; ENOENT → friendly "install git" error.
  - `src/provider.ts` — `RefTaskProvider` class. `init()` verifies cwd is a git repo and fails fast on `schema: backlog` (filename convention has no analogue in a ref-only store). `create()` allocates the next ID by scanning existing refs (`git for-each-ref refs/ordna/tasks/*`), then CAS-writes with `expected-old = ""` (must-not-exist) so two offline machines can't both end up at T-N. `update()` reads the current OID, builds the new blob, CAS-writes with the captured OID as `expected-old` — protects against in-flight concurrent writers. `move()` reuses `update()`. `delete()` CAS-deletes via `update-ref -d`. `watch()` polls `for-each-ref` every 1 s (configurable via `ref.pollIntervalMs`), diffs against the last snapshot, emits `added`/`changed`/`removed` events. `commit()` is a deliberate no-op. `dispose()` clears the poll timer; idempotent.
  - `src/index.ts` — `createProvider(config, cwd)` factory + `GitRunner` re-export so callers can do raw plumbing if needed.
  - `package.json` is publishable (not private), version `0.1.0`, peer-deps `@frehilm/ordna-core@^0.2.0`.
- 2026-05-14: Tests. 15 integration tests against a real on-disk git repo (created per-test with `mkdtempSync` + `git init`):
  - init failure modes (non-git cwd, `schema: backlog` rejection)
  - create / list / get / update / move / delete round-trips
  - working tree is *never* touched (`readdirSync(cwd)` returns nothing but `.git`)
  - CAS at the git layer: `update-ref` with a wrong `expected-old` is rejected; a correct one succeeds (this is what protects concurrent writers in the read-then-write window — the higher-level `update()` test was rewritten to verify this directly because two sequential `update()` calls each capture fresh state and so don't conflict by themselves)
  - offline-collision allocation: a manually-created `T-001` ref makes the allocator pick `T-002`
  - `commit()` is verified to do nothing (no commits land on `main`)
  - dispose is idempotent
  - the `tasks/` directory is never created across a full create/update/delete sequence
