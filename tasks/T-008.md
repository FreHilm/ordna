## Goal

Ship `@frehilm/ordna-jira` as a separate package implementing the `TaskProvider` interface introduced by T-020 and made loadable by T-022 / T-023. Same TUI / Web UI, swappable backend, configured via `.ordna/config.yaml`.

This is **Phase 2** of T-018. Read-only first (list / get / watch), write support follows in a minor bump.

## Acceptance Criteria

### Read-only milestone (`@frehilm/ordna-jira@0.1.0`)

- [ ] New package `packages/jira/` with `src/{index,provider,client,schema,map}.ts`
- [ ] Exports `createProvider(config, cwd): TaskProvider` per the contract from T-022
- [ ] Auth via env var (e.g. `JIRA_TOKEN`); HTTP Basic with `email:apiToken`
- [ ] Config block in `.ordna/config.yaml`:
  ```yaml
  provider: jira
  jira:
    baseUrl: https://acme.atlassian.net
    email: ...
    apiTokenEnv: JIRA_TOKEN
    projectKey: ENG
    jql: "sprint in openSprints()"
    pollIntervalMs: 30000
  ```
- [ ] Implements `list`, `get`, `watch` (polling-based at `pollIntervalMs`)
- [ ] `kind === "jira"`
- [ ] `Task.remote` populated: `provider: "jira"`, `externalId: <key>`, `url: ${baseUrl}/browse/${key}`, `extras` with sprint / story points / epic
- [ ] Field mapping per the table below; falls back gracefully when fields are missing
- [ ] Rate-limit-aware: respects `Retry-After`, exponential backoff on 429
- [ ] Helpful errors: surface Jira's error message verbatim (especially transition rejections)
- [ ] Tests: unit-test `map.ts` (no network); integration tests stub a Jira HTTP server (similar to existing `agent.test.ts` pattern)
- [ ] `packages/jira/README.md` with setup, supported fields, lossy fields, rate-limit notes

### Write milestone (`@frehilm/ordna-jira@0.2.0` — separate task or follow-up)

- [ ] Implements `create`, `update`, `move`, `delete`
- [ ] Writes restricted to fields Ordna understands: status / assignee / priority / tags / depends_on / sections (description)
- [ ] Remote-only fields stay read-only (sprint, story points, epic, comments)
- [ ] `commit` left undefined (so `ordna commit` errors with a clear message)

## Notes

### Field mapping

| Ordna `Task` field         | Jira REST field                        | Direction |
|----------------------------|----------------------------------------|-----------|
| `id`                       | derived from `key` (`ENG-123` ↔ `T-123` if `idPrefix:T`, else verbatim) | r/w |
| `title`                    | `fields.summary`                       | r/w |
| `status`                   | `fields.status.name` (lowercase)       | r/w |
| `assignee`                 | `fields.assignee.displayName` (single) | r/w |
| `priority`                 | `fields.priority.name` → `high`/`medium`/`low` | r/w |
| `tags`                     | `fields.labels`                        | r/w |
| `depends_on`               | issuelinks where `type == "Blocks"` (inverse) | r/w |
| `sections`                 | `fields.description` → single `Description` section (markdown via ADF parser) | r/w |
| `created_at`               | `fields.created` (ISO date prefix)     | r |
| `updated_at`               | `fields.updated`                       | r |
| `remote.externalId`        | `key`                                  | r |
| `remote.url`               | `${baseUrl}/browse/${key}`             | r |
| `remote.extras.sprint`     | `customfield_<N>` (sprint)             | r |
| `remote.extras.storyPoints`| `customfield_<N>` (story points)       | r |
| `remote.extras.epic`       | `customfield_<N>` (epic link)          | r |
| Comments / watchers / reporter | not mapped                         | — |

### Watch strategy

- v1: polling at `pollIntervalMs` (default 30s). Diff against last snapshot; emit `added` / `changed` / `removed`.
- v2: webhook receiver (requires public URL); deferred.

### depends_on gate

Stays a client-side rule in core (T-023). Jira's own workflow rules may also reject the transition; both errors surface to the user.

### Status names

If T-018's "dynamic statuses" decision lands, Jira plugin returns the project's actual workflow states from `provider.statuses?()` so the board uses native column names ("In Progress", "Code Review", "Done") rather than Ordna's defaults.
