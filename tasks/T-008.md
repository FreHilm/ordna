## Goal

Ship `@frehilm/ordna-jira` as a separate package implementing the `TaskProvider` interface introduced by T-020 and made loadable by T-022 / T-023. Same TUI / Web UI, swappable backend, configured via `.ordna/config.yaml`.

This is **Phase 2** of T-018. Read-only first (list / get / watch), write support follows in a minor bump.

## Notes

### Field mapping

| Ordna `Task` field         | Jira REST field                        | Direction |
|----------------------------|----------------------------------------|-----------|
| `id`                       | derived from `key` (`ENG-123` ↔ `T-123` if `idPrefix:T`, else verbatim) | r/w |
| `title`                    | `fields.summary`                       | r/w |
| `status`                   | `fields.status.name` (lowercase)       | r/w |
| `assignee`                 | `fields.assignee.displayName` (single) | r/w |
| `priority`                 | `fields.priority.name` → `high`/`medium`/`low` | r/w |
| `tags`                     | `fields.labels`                        | r/w |
| `depends_on`               | issuelinks where `type == "Blocks"` (inverse) | r/w |
| `sections`                 | `fields.description` → single `Description` section (markdown via ADF parser) | r/w |
| `created_at`               | `fields.created` (ISO date prefix)     | r |
| `updated_at`               | `fields.updated`                       | r |
| `remote.externalId`        | `key`                                  | r |
| `remote.url`               | `${baseUrl}/browse/${key}`             | r |
| `remote.extras.sprint`     | `customfield_<N>` (sprint)             | r |
| `remote.extras.storyPoints`| `customfield_<N>` (story points)       | r |
| `remote.extras.epic`       | `customfield_<N>` (epic link)          | r |
| Comments / watchers / reporter | not mapped                         | — |

### Watch strategy

- v1: polling at `pollIntervalMs` (default 30s). Diff against last snapshot; emit `added` / `changed` / `removed`.
- v2: webhook receiver (requires public URL); deferred.

### depends_on gate

Stays a client-side rule in core (T-023). Jira's own workflow rules may also reject the transition; both errors surface to the user.

### Status names

If T-018's "dynamic statuses" decision lands, Jira plugin returns the project's actual workflow states from `provider.statuses?()` so the board uses native column names ("In Progress", "Code Review", "Done") rather than Ordna's defaults.

## Progress

- 2026-05-11: Started. Decisions confirmed with user: (1) Build now against workspace core in `packages/jira/`, publish after 0.2.0 ships. (2) Hand-roll a small ADF→markdown converter (~100 LOC, no deps). (3) Auto-discover custom field IDs (sprint / story points / epic) via `/rest/api/3/field` at init. (4) Plugin overrides `config.statuses` from Jira's project workflow at init — board columns become "To Do / In Progress / Code Review / Done" automatically. Scope is the read-only milestone only (list / get / watch); write milestone is a separate follow-up task.
- 2026-05-11: Implemented. New package `packages/jira/` (~750 LOC source + ~430 LOC tests + README). Files:
  - `src/schema.ts` — narrow TS types for the Jira REST v3 response slice we consume (search, issue, fields, ADF nodes, project statuses).
  - `src/client.ts` — HTTP client with Basic auth, pagination, retry policy (429 honours `Retry-After`; transient 5xx gets exponential backoff with jitter; up to 3 retries). Error bodies parsed to surface `errorMessages` / `errors` arrays verbatim.
  - `src/adf.ts` — hand-rolled ADF→markdown converter for paragraphs, headings, bullet/ordered lists (with nesting), code blocks, blockquotes, horizontal rules, hard breaks, mentions, emoji, inline cards, plus `strong`/`em`/`code`/`strike`/`link` marks. Unknown nodes fall through to their inner content so nothing is lost silently.
  - `src/map.ts` — pure issue → Task mapping. Handles ID rewriting both ways (`ENG-7` ↔ `T-007` respecting `idPrefix` and `zeroPaddedIds`), priority mapping (`Highest`/`High`→`high`, `Lowest`/`Low`→`low`, others null), inward `Blocks` link extraction for `depends_on`, sprint extraction (modern array shape and legacy toString fallback), story points, epic.
  - `src/provider.ts` — `JiraTaskProvider` class. `init()` validates auth implicitly via the first HTTP call, discovers custom field IDs by name match, and overrides `config.statuses` with the project's workflow states (lowercased, in order). `list/get` implemented; `create/update/move/delete` stubbed with clear "not implemented in 0.1.x" errors. `watch()` runs a single polling loop with diff-based event emission; `dispose()` clears the timer and is idempotent.
  - `src/index.ts` — `createProvider(config, cwd)` factory + selected re-exports.
- 2026-05-11: Tests. 31 tests across 3 files:
  - `adf.test.ts` (11) — every node type the converter handles, plus the unknown-node fallthrough.
  - `map.test.ts` (14) — ID rewriting both ways, priority mapping (including Highest/Lowest), depends_on extraction filtering by link type, description ADF→markdown, sprint/story points custom field reads.
  - `provider.test.ts` (6) — integration with a `node:http` stubbed Jira server (same pattern as `web/agent.test.ts`). Covers init-time discovery of custom fields and statuses, list mapping, get-by-Ordna-id roundtrip, 404→null, 429 retry-and-succeed, dispose idempotency.
- 2026-05-11: All 5 workspace packages typecheck and build clean. Test totals: core 29 / web 9 / cli 11 / jira 31 = 80 (up from 49 after T-024). Mock-provider has no tests of its own.
