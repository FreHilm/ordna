## Notes

**Changeset wording (drop in `.changeset/plugin-architecture.md`):**

```markdown
---
"@frehilm/ordna-core": minor
"@frehilm/ordna-web": minor
"@frehilm/ordna-cli": minor
---

Introduce pluggable storage backends via the new `TaskProvider` interface.
The built-in `FileTaskProvider` is the default; external providers can be
configured via `provider:` in `.ordna/config.yaml` and will be loaded from
`@frehilm/ordna-<name>` if installed.

BREAKING: `createContext` is now async. All consumers must `await` it.
The CLI / TUI / web entrypoints handle this internally; only library
consumers (e.g. embedding `@frehilm/ordna-core` directly) need to update.
```

**Why this is a separate task, not part of T-023/T-024:**

Each previous attempt to ship pulled the release machinery forward into the implementation task, and the work-in-progress couldn't be tested cleanly without committing to a version. Splitting the release out means: the loader (T-022), the lifecycle (T-023), and the docs + verification (T-024) can all be built, exercised, and rolled back if something turns out to be wrong — without the public registry ever seeing it. The release becomes one tight, deliberate commit.

**Auth reminder:**

Account uses a passkey, so the npm token must have the **bypass-2FA** flag set; without it, `pnpm publish` fails with a misleading 404. The `0.1.3` publish flow established the working pattern: granular access token with `@frehilm/*` scope, read+write, bypass-2FA enabled.

**Post-release follow-ups (separate tasks, not part of this one):**

- T-008 (Jira plugin) becomes unblocked once 0.2.0 is on npm — external packages can now declare a peer dep on `@frehilm/ordna-core@^0.2.0` and export `createProvider`.
- T-009 (Linear plugin) similarly unblocked.
- T-025 (ref-based provider) and T-026 (sync ref for ID allocation) become viable additions, both opt-in.
