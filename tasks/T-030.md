## Goal

Introduce an **internal** `Backend` interface inside `@frehilm/ordna-core` and refactor the current file-IO logic in `store.ts` into a `FileBackend` class that implements it. Public API is unchanged — `listTasks`, `createTask`, `updateTask`, etc. stay sync-compatible (where they already are) and keep the same signatures. `createContext` stays sync.

This is the foundation for hybrid mode (T-031) and namespace mode (T-032). It's deliberately a no-behavior-change refactor: shipping just this task should leave every existing test green with no observable difference for users.

The interface is **private** — never exported from core's `index.ts`. There's no plugin loader, no dynamic import, no `@frehilm/ordna-<name>` mechanism. Future modes ship as additional internal classes inside core.

## Notes

### Why lazy init

Keeping `createContext` synchronous is non-negotiable — the IDE Fredrik is building embeds core, and an async `createContext` ripples through every consumer. The lazy-init pattern means: backend objects are cheap to construct (no I/O), and the first method call pays the I/O cost. Every subsequent call hits a cached promise.

Pattern:

```ts
class FileBackend implements Backend {
  #initPromise: Promise<void> | null = null;

  async #ensureInit(): Promise<void> {
    if (!this.#initPromise) this.#initPromise = this.init();
    return this.#initPromise;
  }

  async init(): Promise<void> { /* ensureTasksDir, etc. */ }

  async list(opts?: ListOptions): Promise<Task[]> {
    await this.#ensureInit();
    // ... actual logic
  }
}
```

### Module layout rationale

The four files in `storage/` are organised by what gets shared with future backends:

| Module | file | hybrid (T-031) | namespace (T-032) |
|---|---|---|---|
| `markdown.ts` | ✓ | ✓ | ✓ |
| `file-io.ts` | ✓ | ✓ | — |
| `git-ref.ts` (added in T-031) | — | ✓ | ✓ |
| `sync-ref.ts` (added in T-031) | — | ✓ | — |

So T-030 ships only what `file` needs. T-031 and T-032 add their own modules.

### Out of scope for T-030

- No `storage:` config key yet (lands in T-031 with the first non-file backend)
- No git ref operations
- No auto-detect logic (T-033)
- No behavior change for users
