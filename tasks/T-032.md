## Goal

Add a third storage mode, `storage: namespace`, that stores tasks as git blobs under `refs/ordna/tasks/<id>` and never touches the working tree. For users who want git-native, decentralized task management without `tasks/` polluting their repo. Inspired by [git-bug](https://github.com/git-bug/git-bug)'s ref-namespace approach, but deliberately simpler — one blob per task at one ref per task; no CRDT op-log.

After this lands, switching a project to namespace mode is one config line:

```yaml
# .ordna/config.yaml
storage: namespace
```

Tasks become invisible to the working tree. `git status` stays clean. `git log` on regular branches doesn't see task mutations. Cross-machine sync via standard git push/fetch on the ref namespace.

- [x] Reuses `storage/auto-push.ts` (PushQueue) from T-031, configured with refspec `+refs/ordna/tasks/*:refs/ordna/tasks/*`
- [x] **Does NOT use `SyncRef` in v1** — the allocator scans existing task refs, and audit log is deferred (see Out of scope)

### Behavior

- [x] `NamespaceBackend.init()`: `ensureRepository` only. No `ensureTasksDir` (working tree must stay untouched).
- [x] `NamespaceBackend.create()`:
  1. Allocate next id by scanning `refs/ordna/tasks/*` and finding the max numeric id (re-use `parseId` from `ids.ts`); increment
  2. Build the markdown bytes via `serializeTask`
  3. `hashObject` → new OID
  4. `updateRef("refs/ordna/tasks/<id>", oid, "" /* empty = must-not-exist CAS */)`
  5. `pushQueue.schedule()`
- [x] `NamespaceBackend.update()`:
  1. `forEachRef` to find the current OID for `refs/ordna/tasks/<id>` (404 if missing → throw `Task <id> not found.`)
  2. `catBlob` → existing bytes → parse → merge patch
  3. `hashObject` → new OID
  4. `updateRef(refname, newOid, currentOid /* CAS expected-old */)` — fails non-fast-forward if another writer changed the ref between read and write
  5. `pushQueue.schedule()`
- [x] `NamespaceBackend.delete()`: `deleteRef(refname, expectedOid)` (CAS) + `pushQueue.schedule()`
- [x] `NamespaceBackend.list()`: `forEachRef("refs/ordna/tasks/*")` → `catBlob` each → `parseTaskBytes` → apply `ListOptions` filters → sort by id
- [x] `NamespaceBackend.get()`: targeted `forEachRef` for the specific ref name → `catBlob` → `parseTaskBytes`; null if ref doesn't exist
- [x] `NamespaceBackend.watch()`: polling at `pollIntervalMs` (default 1s, configurable via `namespace.pollIntervalMs` in config). Each tick: `forEachRef` → diff against last snapshot by (refname, oid). Emit standard `TaskEvent` events.
- [x] `NamespaceBackend.commit()`: **deliberate no-op**. Tasks live outside the working tree; there's nothing to `git add`. Don't alias to push — that would surprise users with unexpected network calls. The auto-push handles sync silently.
- [x] `NamespaceBackend.dispose()`: clear poll timer, await `pushQueue.flush()` so any pending coalesced push completes before exit

### CAS semantics

- [x] Create-time CAS uses empty-string expected-old to require the ref doesn't exist yet (defends against two offline machines both writing T-001)
- [x] Update-time CAS uses the captured current OID — fails non-fast-forward if another writer slipped in. Surface a clear "ref moved underneath; pull and retry" error.
- [x] No fetch-on-conflict retry in v1 (different from T-031's SyncRef pattern — for individual task refs, the user-visible "ref moved" is meaningful; auto-retry would mask intentional concurrent edits)

### Filename / id semantics

- [x] Stored bytes are the same markdown + frontmatter `FileBackend` writes. A task round-trips between modes byte-identically if a user migrates.
- [x] Parsed `Task` objects have `filePath` UNSET (not an empty string — actually omitted, since `Task.filePath` is optional in the schema). UI code already null-guards this field; verify the CLI doesn't crash when it's missing.
- [x] Ref name format: `refs/ordna/tasks/<id>` where `<id>` is the literal Ordna id (e.g., `T-001`). No filename slugs, no `task-1 - title.md` style.

## Notes

### What's different from hybrid

| Aspect | Hybrid (T-031) | Namespace (T-032) |
|---|---|---|
| Where task bytes live | Files in `tasks/*.md` | Blobs in `refs/ordna/tasks/<id>` |
| Allocator | CAS-bumped `next_id` field in `refs/ordna/state` | `forEachRef` to find max + 1 |
| Audit log | `ops` array in `refs/ordna/state` | Not implemented in v1 (deferred) |
| Watcher | chokidar on `tasksDir` | Polling `forEachRef` (default 1s) |
| Working tree | `tasks/*.md` present | Completely untouched |
| Auto-push refspec | `refs/ordna/state:refs/ordna/state` | `+refs/ordna/tasks/*:refs/ordna/tasks/*` |
| `commit()` | `git add tasksDir && git commit` | No-op |

### Watch implementation

Refs don't have a kernel-level change-notification path. Reading `.git/refs/` directly breaks the moment git packs refs. Polling at 1s is simple, reliable, and cheap (one `git for-each-ref` call per tick — sub-millisecond on modern hardware for a few hundred refs).

### Tasks/ directory: explicit absence

Namespace mode must NEVER create `tasks/`. The "working tree stays clean" property is the whole point. The test suite verifies this explicitly with `readdirSync(cwd).filter(n => n !== '.git')` returning empty after a full create/update/delete cycle.

### Sync UX

Same auto-push posture as hybrid (Fredrik's decision): every mutation schedules a coalesced push, best-effort, silent on failure. Users who want to sync explicitly can also run:

```sh
git push origin '+refs/ordna/tasks/*:refs/ordna/tasks/*'
git fetch origin '+refs/ordna/tasks/*:refs/ordna/tasks/*'
```

Documenting the refspec config in the README is part of T-033's docs work.

### Out of scope for T-032

- Audit log (deferred — can later use the same `SyncRef` machinery from T-031 with only the `ops` field populated, keeping `next_id` unused)
- `ordna sync` CLI command (the manual refspec is documented; CLI wrapper is a follow-up)
- Migration tooling between modes (file ↔ namespace) — deferred
- Auto-detect (T-033)

### Risk: T-031 + T-032 both touch `storage/git-ref.ts`

If both ship in parallel, coordinate on the GitRunner API surface — add methods additively, agree on shared types like `{refname, oid}`. Whichever task lands second extends the module rather than redesigning.

  - `dispose()`: clear poll timer, drain `PushQueue.flush()`, clear listeners + snapshot.
