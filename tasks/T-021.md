## Goal

Move all file-system logic currently in `packages/core/src/store.ts` (and parts of `watcher.ts`, `git.ts`, `parser.ts`) into a single `FileTaskProvider` class implementing the `TaskProvider` interface from T-020. After this PR, the file logic exists as a self-contained provider, but `store.ts` still wraps it transparently — no consumer-visible change.

## Acceptance Criteria

- [x] New file `packages/core/src/providers/file.ts` exports `FileTaskProvider` class
- [x] `FileTaskProvider implements TaskProvider` (T-020)
- [x] All file-touching logic (chokidar watcher, git wrapper, ID allocation, parser/writer calls) lives inside the class or its private helpers
- [x] `FileTaskProvider.kind === "file"`
- [x] `commit()` is implemented (delegates to existing `commitTasks` git logic)
- [x] `init()` ensures the tasks directory exists; `dispose()` closes any open watchers
- [x] `store.ts` is reduced to thin wrappers that delegate to the provider via `ctx.provider.<method>()`
- [x] No exported function signatures change in this PR — only their bodies
- [x] All 20 existing core tests still pass without modification

## Notes

`store.ts` becomes a delegation layer:

```ts
export const listTasks  = (ctx, opts?) => ctx.provider.list(opts);
export const getTask    = (id, ctx)    => ctx.provider.get(id);
// etc.
```

The `depends_on` gate stays in core (in `moveTask`), not in the provider — providers shouldn't have to re-implement Ordna's business rules.

`commitTasks` stays in core but throws a clear error if the active provider doesn't implement `commit()`. Today only `FileTaskProvider` will.

T-022 will swap `store.ts`'s direct `new FileTaskProvider(...)` calls for the dynamic loader. This task hard-codes the file provider; T-022 makes it pluggable.
